# voice-to-goal 変換例とチェックリスト

SKILL.md の補助資料。多様な口述パターンの Before → After と、仕上がり点検用チェックリスト。

## 仕上がりチェックリスト

整形した目標を貼り出す前に、次を満たしているか自問する:

- [ ] **一文の目的**が冒頭にあり、成果物が何か一読で分かる
- [ ] 各完了条件が**観察可能**（達成/未達成を客観的に切り分けられる）
- [ ] 「良い/きれい/使いやすい」等の**主観的形容詞**を、確認できる事実へ翻訳済み
- [ ] **自己検証の指示**が入っている（Claudeが実演して会話に結果を出す導線）
- [ ] **改行なしの1行**で、条件は `(1)(2)(3)` のインライン列挙
- [ ] フィラー・言い直しが除去され、要求だけが残っている
- [ ] 補った仮定はコードブロック外に明示した
- [ ] 入力の言語と揃っている
- [ ] 4000文字以内。暴走リスクがあれば `またはNターンで停止する` を付与

## 変換例

### 例1: 単一機能のWebアプリ

**入力（音声）:**
「なんかこう、ポモドーロタイマー作りたいんだよね。25分計って、終わったら音鳴って、休憩5分。ブラウザで動けばいい、シンプルでいい。」

**出力:**
```
/goal ブラウザだけで動くポモドーロタイマー(単一HTML)を作成する。完了条件は以下を全て満たすこと:(1)HTMLを開くだけで動作し外部依存がない(2)開始すると25分のカウントダウンが分:秒で表示される(3)25分終了時に通知音が鳴り、自動で5分の休憩カウントダウンに切り替わる(4)開始/一時停止/リセットができる。完成後、実際にブラウザ(またはヘッドレス)で開いて各条件を自分で確認し、結果を報告すること。
```
※「シンプルでいい」は単一HTML・追加ライブラリなしと解釈しました。

### 例2: 調査・リサーチ

**入力（音声）:**
「競合のプライシングを調べてまとめてほしいんだけど、主要な3社くらいでいいから、表にして比較できるようにして。」

**出力:**
```
/goal 主要競合3社の料金プランを調査し比較表にまとめる。完了条件は以下を全て満たすこと:(1)対象3社の名称・各プラン名・月額料金・主要な含有機能が表形式で整理されている(2)各データに出典URLが併記されている(3)3社を横並びで比較できる形式になっている。完成後、表の各セルが埋まっていること・出典が付いていることを自分で点検し、抜けがあれば補ってから結果を提示すること。
```
※ 対象3社が未指定のため、調査の中でシェア上位3社を選定する前提にしています。特定の3社があれば教えてください。

### 例3: リファクタ／移行

**入力（音声）:**
「あの古いAPIの呼び出しを新しいのに全部置き換えたいんだよね、コンパイル通って、テストも壊れないようにして。」

**出力:**
```
/goal 旧APIの呼び出しを新APIへ全面移行する。完了条件は以下を全て満たすこと:(1)旧APIへの参照がコードベースから無くなっている(該当シンボルの検索結果が0件)(2)プロジェクトがビルド/コンパイルを通る(3)既存テストが全てpassする。各ターンで、旧API検索結果・ビルド結果・テスト結果を提示し、3点が満たされたことを自分で確認して示すこと。または25ターンで停止する。
```
※ 旧/新APIの具体名は最初のターンでコードから特定する前提です。

### 例4: ドキュメント作成

**入力（音声）:**
「READMEがもう古くて実態と合ってないから、ちゃんと今の使い方に直してほしい。インストール手順と使用例は必須で。」

**出力:**
```
/goal README を現在の実装に合わせて更新する。完了条件は以下を全て満たすこと:(1)インストール手順が記載され、記載どおりの手順で実際にセットアップが完了する(2)最低1つの使用例(コマンドまたはコード)があり、それが実際に動作する(3)実装に存在しない機能・古い記述が残っていない。完成後、インストール手順と使用例を自分で実行して再現できることを確認し、結果を報告すること。
```

### 例5: とても曖昧 → 1問だけ確認するケース

**入力（音声）:**
「売上のデータ、なんかいい感じにまとめて見せてほしい。」

このレベルで成果物の核（Web/PDF/スプレッドシート、集計軸）が全く不明な場合は、
`AskUserQuestion` で**成果物の形式**だけ1問確認してから整形する。仮定で突っ走ると
成果物ごと外す危険があるため。確認が取れたら例1〜4と同じ粒度で整形する。

## アンチパターン（避けるべき出力）

- **検証不能:** 「売上を分かりやすくまとめる」→ 何をもって完了か判定できない
- **主観条件:** 「見やすいグラフを作る」→「◯◯別の値を示す棒グラフが表示される」に翻訳する
- **自己検証欠落:** 条件は良いが「自分で確認して報告」が無い → 判定モデルに達成が見えにくい
- **改行入り:** 途中改行があると `/goal` 貼り付け時に途中送信され得る → 1行に畳む
- **聞き返しすぎ:** 仮定で十分埋まるのに質問を重ねる → /goal の「聞き返さず着手」思想に反する
