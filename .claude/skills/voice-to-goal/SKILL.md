# voice-to-goal

口述された曖昧な「やりたいこと」を、`/goal` にそのまま貼れる**検証可能な目標プロンプト**へ整形するスキル。

## なぜこの整形が必要か（/goal の仕組み）

`/goal <条件>` は、**セッション中のStopフック**として働く。毎ターン終了時に小型モデルが
「会話にこれまで現れた内容」だけを見て条件の達成可否を判定し、満たされるまでClaudeを走らせ続け、
満たされた瞬間に自動でクリアされる。判定モデルは**自分でツールを実行しない**——見えるのは
Claudeが会話に提示した出力だけ。

ここから、良い目標条件の性質が決まる:

- **観察可能な終了状態**であること。「良い感じにする」ではなく「ブラウザで開くと合計が表で出る」「`npm test` が全部pass」のように、達成/未達成が客観的に切り分けられる。
- **Claude自身が達成を"実演"して会話に示す**ことを条件に組み込む。判定モデルはコマンドを叩けないので、「Claudeが実際に◯◯して結果を報告すること」まで書いておくと、達成が会話上に現れて正しく判定される。
- **一発で指示として機能する**こと。/goal は条件文をそのまま作業指示として扱い、Claudeはユーザーに聞き返さず着手する。だから条件文は自己完結していなければならない。

制約: 条件は最大 **4000文字**。暴走が心配なタスクは末尾に `または N ターンで停止する` を足せる。

## 整形の手順

1. **意図を抽出する。** 口述には言い淀み・フィラー（「えーっと」「なんか」「みたいな」）や言い直しが混ざる。
   捨てるものと、本当の要求を分ける。中心となる成果物・目的を一文で言い切れる形にする。
2. **暗黙の成功条件を明示化する。** ユーザーは完了条件を口に出さないことが多い。話の内容から、
   達成を客観的に確認できる条件を**こちらが補って**具体化する（例:「グラフも欲しい」→「月別合計の棒グラフが表示される」）。
3. **各条件を観察可能にする。** 形容詞（「使いやすい」「きれいな」）を、確認できる事実へ翻訳する。
4. **自己検証の指示を必ず入れる。** 「完成後、実際に◯◯して各条件が満たされていることを自分で確認し、結果を報告すること」。
   これが判定モデルに達成を見せる導線になる。
5. **入力の言語に合わせる。** 日本語で話されたら日本語の目標に。
6. **1行に収める。** `/goal` へ貼るとき改行で途中送信されないよう、**ハードな改行を入れず**、
   条件は `(1) (2) (3)` とインラインで列挙する。

## 出力フォーマット

必ず、そのまま貼れる**コードブロック**で提示する（`/goal ` プレフィックス込み）。その下に一言、
どう解釈したか／何を補ったかを添える。

````
```
/goal <目的を一文で>。完了条件は以下を全て満たすこと:(1)<観察可能な条件>(2)<観察可能な条件>(3)<観察可能な条件>。完成後、<具体的な検証手段>で各条件が満たされているか自分で確認し、結果を報告すること。
```
````

**注意:** Claude はチャット内で `/goal` スラッシュコマンドを自分で打てない。このスキルの成果物は
「貼り付け用テキスト」であり、実際に発動するのはユーザーが貼って送信したとき。その旨を一言添える。

## 曖昧な入力の扱い

口述が曖昧でも、まずは**合理的な仮定を置いて一発で整形する**のが基本（/goal 自体が「聞き返さず着手」の思想）。
仮定はコードブロックの下に「※ ◯◯と仮定しました。違えば言ってください」と明示する。
ただし、成果物の種類そのものが不明（例:「レポート」がPDFなのかWebなのか作業の核が変わる）で仮定が乱暴になる場合のみ、
`AskUserQuestion` で**1つだけ**核心を確認してから整形する。質問攻めにはしない。

## 例

**入力（音声）:** 「えーっと、経費精算のCSVをこう、月ごとに集計したくて、合計とか出して、あとグラフも欲しいかな、Excelっぽく見れるといいな、うん」

**出力:**
```
/goal 経費精算CSVを月ごとに集計して表示するHTMLレポートを作成する。完了条件は以下を全て満たすこと:(1)ブラウザでレポートを開くと月ごとの合計金額が表形式で表示される(2)月別合計の棒グラフが表示される(3)元のCSVを読み込んで自動集計している。完成後、実際にレポートをブラウザ(またはヘッドレス)で開き、各条件が満たされていることを自分で確認して結果を報告すること。
```
※「Excelっぽく」はWeb表＋棒グラフと解釈しました。単一HTMLで良い前提です。違えば教えてください。

**入力（音声）:** 「認証まわりのテストがなんか落ちてる気がするから直したい、全部通るようにして、あ、でも他のテストは触らないでほしい」

**出力:**
```
/goal test/auth 配下のテストが全て通る状態にする。完了条件は以下を全て満たすこと:(1)該当するテストコマンド(例:npm test test/auth)を実行すると全てpassする(2)test/auth 以外のテストファイルを一切変更していない(3)lintが通る。各ターンでテスト実行結果とgit diffの範囲を提示し、全pass・変更がauth配下のみであることを自分で確認して示すこと。または20ターンで停止する。
```
※ テストランナーは仮にnpmとしています。実際のコマンドに読み替えてください。
