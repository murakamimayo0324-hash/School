# goal-prompt-builder — 「やりたいこと」を /goal 用プロンプトへ整形する

ユーザーが音声や口頭でラフに話した「やりたいこと」を受け取り、Claude Code の
`/goal` コマンドにそのまま貼り付けられる**検証可能な完了条件**へ整形する。

## なぜ整形が必要か（前提の理解）

`/goal` は完了条件を渡すとターンを跨いで自走し、**毎ターン終了後に小型の評価モデル
（既定 Haiku）が「条件を満たしたか Yes/No」を判定**する。ここが肝心で、
**評価モデルは会話（transcript）に出力された内容しか見られない**。ファイルを開いたり
コマンドを独自に実行したりはできない。

したがって良い条件とは「Claude 自身の出力（テスト結果・終了コード・件数など）で
Yes/No を証明できる、測定可能な終了状態」である。ラフな発話（例:「認証まわり直しといて」）
は主観的で検証できないため、そのまま渡すと評価が空回りする。この乖離を埋めるのがこのスキルの役目。

判断に迷う細部・良い例/悪い例の対比・よくある失敗は
[references/goal-condition-guide.md](references/goal-condition-guide.md) を参照する。

## ワークフロー

### 1. 入力を汲む
音声書き起こしはフィラー・言い淀み・同音異義の誤変換を含む前提で、**言葉尻でなく意図**を
取る。「〜みたいな」「えーと」等は無視し、本当に達成したい終了状態を推定する。

### 2. 4要素を抽出する
発話から次を拾う。埋まらない要素は次のステップで補う。

- **測定可能な終了状態** — テストの合否 / ビルドの終了コード / 対象ファイル数 / 未対応件数がゼロ / キューが空 など、数えられる・判定できる状態
- **証明方法** — その状態を**会話に出力される形**でどう示すか（例: `npm test` が exit 0、`git status` がクリーン、対象コマンドの出力）
- **守るべき制約** — 途中で壊してはいけないもの（例: 他のテストファイルは変更しない、公開 API を変えない）
- **ターン/時間上限** — 暴走防止の停止条件（例: `20ターンで停止` / `or stop after 20 turns`）

### 3. 不足だけを最小限に補完する
音声のラフさを尊重し、**質問攻めにしない**。特に「完了をどう判定するか（証明方法）」が
発話から分からない場合のみ、的を絞って 1〜2 個だけ確認する（例:「完了の判定はテストで
よいですか、それとも別の基準がありますか？」)。それ以外は妥当な既定で埋め、**埋めた点は
出力の「前提」に必ず明記**してユーザーが上書きできるようにする。

### 4. 条件文へ整形する
4要素を 1〜数文の条件にまとめる。原則:

- **主観語を検証可能語に翻訳する。** 「綺麗にする」→「lint が exit 0」、「直す」→「該当テストが通る」。
- **証明を会話に残す指示に変換する。** 「他ファイルを変えない」のような制約は評価モデルが
  自力で確認できないため、「**毎ターン `git status` を出力し、対象外ファイルが未変更であること**」の
  ように、証拠が transcript に出る形へ言い換える。
- **必ずターン/時間上限を付ける。** 上限なしは無限ループの温床。
- **入力言語に合わせる。** 日本語の発話なら日本語の条件文でよい（評価モデルは日本語も解する）。
- **4,000 文字以内**に収める。

### 5. 出力する
下記テンプレートで、コピペ即実行できる形で返す。**説明で埋めず、まず `/goal` 行を出す**。

```
## 整形結果

/goal <整形済みの完了条件（1〜数文、4要素入り）>

**前提**: <補完・仮定した点／曖昧だった点。無ければ「なし」>
**実行のヒント**: 未許可コマンドの都度確認を消して無人で走らせるなら auto mode の併用を推奨。
```

## Before / After 例

**例1**
入力（音声）: 「認証まわりのテスト落ちてるっぽいから直しといて」
出力:
```
/goal test/auth 配下のテストが全て通り(`npm test -- test/auth` が exit 0 で、その出力を提示)、`git status` がクリーンであること。他のテストファイルは変更しない（毎ターン `git status` を出力して確認）。20ターンで停止。
```

**例2**
入力（音声）: 「この大きいファイル、責務ごとに分割したいんだよね」
出力:
```
/goal src/bigmodule.ts を責務ごとのモジュールへ分割し、各ファイルが300行未満(分割後に各ファイルの行数を出力して提示)、`npm run build` が成功、既存の公開 API は不変であること。15ターンで停止。
```

**例3**
入力（音声）: 「未対応のドキュメント、今週マージしたぶん全部書いといて」
出力:
```
/goal CHANGELOG.md に、今週マージされた各 PR に対応するエントリが存在する状態(対象 PR 一覧と CHANGELOG の該当行を毎ターン提示して照合)。既存エントリは削除しない。10ターンで停止。
```

## 品質チェック（返す前に自己確認）

- `/goal ` で始まる貼り付け可能な1ブロックになっているか
- 終了状態・証明方法・制約・ターン上限の**4要素が揃っている**か
- 評価モデルが **transcript だけで** Yes/No を判定できるか（ファイルを開かず判定可能か）
- 補完/仮定した点を「前提」に明記したか
- 4,000 文字以内か
